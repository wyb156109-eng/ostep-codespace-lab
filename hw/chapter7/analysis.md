## Q1 FIFO 預測

Job 0：最先執行。響應時間 = 0，周轉時間 = 200。

Job 1：等 Job 0 執行完。響應時間 = 200，周轉時間 = 400 (200+200)。

Job 2：等 Job 1 執行完。響應時間 = 400，周轉時間 = 600 (400+200)。

平均響應時間 (Average Response Time) = (0 + 200 + 400) / 3 = 200

平均周轉時間 (Average Turnaround Time) = (200 + 400 + 600) / 3 = 400
 
 ## Q1 結論
當所有工作的長度都相同時（皆為 200），SJF (最短任務優先) 的表現與 FIFO 完全一樣。因此 SJF 的平均響應時間也是 200，平均周轉時間也是 400。

## Q2 FIFO 預測
Job 0 (長度 100)：最先執行。響應時間 = 0，周轉時間 = 100。

Job 1 (長度 200)：等 Job 0 (100) 執行完。響應時間 = 100，周轉時間 = 100 + 200 = 300。

Job 2 (長度 300)：等 Job 1 執行完 (此時時間是 300)。響應時間 = 300，周轉時間 = 300 + 300 = 600。

平均響應時間 = (0 + 100 + 300) / 3 = 133.33

平均周轉時間 = (100 + 300 + 600) / 3 = 333.33

 ## Q2 結論
 因為這次的工作長度剛好是「由短到長」排列 (100, 200, 300)，SJF (最短任務優先) 不需要進行任何重新排序。因此，在這種工作本身就已經是「最短優先」排列的情況下，SJF 的結果會和 FIFO 完全一模一樣。

## Q3 RR 預測

響應時間極佳：因為時間片設定為 -q 1，排程器會每 1 單位時間就切換一次工作。Job 0 會在時間 0 開始，Job 1 在時間 1 開始，Job 2 在時間 2 開始。因此，平均響應時間預測為 (0 + 1 + 2) / 3 = 1。   周轉時間變差：RR 策略會讓所有工作交替執行，導致每個工作的完成時間都被大幅延後，因此周轉時間一定會比 FIFO 或 SJF 差很多。

## Q3 结论
验证结果符合预期。RR 调度器极大地优化了平均响应时间（1.00），但代价是平均周转时间变得非常糟糕（465.67）。这证明了公平性（响应时间）与性能（周转时间）之间存在固有的权衡（Inherent trade-off）。

## Q5
當所有工作的長度都相同，而且 RR 的時間片 (Quantum) 大於或等於工作長度時（Quantum ≥ Job Length），SJF 和 RR 的響應時間會相同。因為這時候 RR 不會中途切換（搶占）工作，每個工作都會一次執行完，這跟 SJF 的行為就一樣了。

## Q6

隨著工作長度增加，SJF 的響應時間會線性增加。因為在 SJF 中，較長的工作必須等待前面所有較短的工作全部執行完畢。前面工作的執行時間變長，後面工作的等待（響應）時間就會等比例增加。

## Q7 

隨著時間片 (Quantum) 增加，RR 的響應時間會跟著變差（增加）。
給定 N 個工作，在最壞情況下，最後一個執行的工作必須等待前面 (N - 1) 個工作各自執行完一個完整的時間片 (q)。因此最壞情況下的響應時間為 (N - 1) × q。
